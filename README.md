## Прогресс

Порядок этапов подстроен под требования к junior DevOps в России (выборка вакансий hh.ru и Хабр Карьеры, октябрь 2026): Ansible важнее Terraform, нужен GitLab CI и эксплуатация баз данных, публичное облако для джуна почти не требуется.

| # | Этап | Практика | Статус |
|---|---|---|---|
| 0 | Git и GitHub flow | Ветки, PR, ревью, конфликты прямо в этом репозитории | ⏳ в работе |
| 1 | [Linux](stages/01-linux/README.md): файловая система, права, процессы, systemd, пакеты, траблшутинг | VM, пользователи, свой systemd-сервис, поиск причины «сервис не стартует» | ⬜ полностью, см. фокус |
| 2 | [Сети](stages/02-networks/README.md): TCP/IP, DNS, HTTP(S), TLS, NAT, SSH, firewall | Диагностика: `dig`, `ss`, `curl`, `tcpdump` | ⬜ полностью, см. фокус |
| 3 | [Bash-скриптинг](stages/03-bash/README.md) | Скрипт бэкапа/мониторинга с `shellcheck` в CI | ⬜ полностью, см. фокус |
| 4 | Виртуализация и домашняя лаборатория: KVM/libvirt, Vagrant | Стенд из нескольких VM на ПК с 32 ГБ, который поднимается одной командой | ⬜ |
| 5 | Веб-серверы: Nginx, reverse proxy, балансировка, TLS | Nginx перед приложением, балансировка на две VM | ⬜ |
| 6 | Базы данных: PostgreSQL | Установка, пользователи и права, бэкапы и восстановление, репликация | ⬜ |
| 7 | Docker и Docker Compose | Контейнеризация, multi-stage build, стек приложение + Nginx + PostgreSQL | ⬜ |
| 8 | Управление конфигурацией: Ansible | Роли и плейбуки, которые настраивают стенд из этапа 4 | ⬜ |
| 9 | CI/CD: GitHub Actions, затем GitLab CI | Пайплайн для `dungeon_deck` (Flutter) в GitHub Actions; свой GitLab в VM и тот же пайплайн в GitLab CI | ⬜ |
| 10 | Python для автоматизации | Утилита для работы с API, с тестами | ⬜ |
| 11 | Мониторинг и логи: Prometheus, Grafana, Loki | Дашборд и алерты для своего сервиса | ⬜ |
| 12 | Kubernetes (база): Pod, Deployment, Service, kubectl, Helm | Задеплоить приложение в k3s или kind | ⬜ |
| 13 | IaC: Terraform (база) | Инфраструктура кодом на локальном провайдере (libvirt или Docker) | ⬜ |
| 14 | Эксплуатация: инциденты, runbook, постмортем | Сломать свой стенд, найти причину, написать постмортем и runbook | ⬜ |
| 15 | Облако (по желанию): Yandex Cloud | Развернуть проект на стартовом гранте | ⬜ |
| 16 | Финальный проект | Код → CI/CD → стенд/k8s → мониторинг → инцидент. Портфолио для резюме | ⬜ |

Входной тест ([Issue #3](../../issues/3)) показал пробелы по Linux, сетям и Bash, поэтому этапы 1–3 проходим полностью. Список слабых тем лежит в README каждого этапа.

Статусы: ⬜ не начат, ⏳ в работе, ✅ закрыт (пройдены все 4 уровня проверки).
